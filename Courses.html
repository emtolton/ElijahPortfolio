  • Caches
    • Cache Entry: Address= [tag(t bits), set(s bits), block offset(b bits)]
    • Cache size = E*S*B
    • #offset bits = log_2(Block Size)
    • #index bits = log_2(# of sets)
    • #tag bits = address size - # offset bits - # index bits
    • Number of blocks = Cache capacity / Block size
    • Cold miss: cache is empty
    • Conflict miss: cache is large enough, but multiple data objects all map to the same level k block.
    • Capacity miss: set of active cache blocks is larger than the cache.

Computer Security

12/15/2025

  • Computer Security Mindset
    • Thinking like an attacker: understand ways security can be circumvented
    • Threat Modeling: Identify assets, threats, and vulnerabilities
    • Thinking like an defender: How can we minimize our vulnerabilities?
    • Availability: users can access info/resources when needed
  • Cryptography
    • Goals of Cryptography
      • Confidentiality: prevent unauthorized access to data
      • Integrity: ensure data is not altered
      • Authentication: verify message origin
    • Randomness
      • True randomness is secure but impractical
      • Pseudo-Random Generator (PRG): expands small random seed into long random-looking output
      • Pseudo-Random Function (PRF): fixed-length output built using PRGs
    • Cipher Metrics
      • Confusion: ciphertext statistically independent of plaintext
      • Diffusion: plaintext changes affect many ciphertext bits
    • Ciphers
      • Substitution Ciphers
        • Caesar Cipher: shifts each letter by a fixed amount
        • Vigenère Cipher: shifts characters using a repeating key
        • Vulnerable to frequency analysis
      • Transposition Ciphers
        • Rearrange plaintext symbols without changing them
        • Examples: columnar, zig-zag, rail fence
        • Low confusion, vulnerable to anagram attacks
      • One-Time Pad (OTP)
        • Key length equals plaintext length
        • Encryption/Decryption: ciphertext = plaintext XOR key
        • Perfect secrecy if key is truly random and never reused
        • Highly impractical due to key management
      • Stream Ciphers
        • Generate keystream using PRG and a random seed
        • Encrypt one bit/byte at a time
        • More practical than OTP but seed must not be reused
      • Block Ciphers
        • Encrypt fixed-size blocks using a reusable key
        • Most common encryption approach today
        • Uses inverse function for decryption
    • Block Cipher Modes
      • Electronic Codebook (ECB)
        • Each block encrypted independently
        • Can be parallelized
        • Low diffusion, reveals patterns
      • Cipher Block Chaining (CBC)
        • Each block XORed with previous ciphertext block
        • Improved diffusion
        • Cannot be fully parallelized
      • Advanced Encryption Standard (AES)
        • Most widely used modern block cipher
    • Hash Functions
      • Accept arbitrary-length input, produce fixed-size output
      • Used for data integrity
      • MD5 and SHA-1 are insecure due to collisions
      • Merkle–Damgård construction chains compression functions
      • Vulnerable to length extension attacks
    • Message Authentication Codes (MAC)
      • Provide integrity and authentication using a secret key
      • HMAC resists length extension attacks
      • HMAC-SHA256 is commonly used
    • Secure Channels
      • Encrypt data for confidentiality
      • Apply MAC for integrity and authentication
    • Hash Attacks
      • Collision Attack: find two messages with same hash
      • Second Pre-image Attack: find a different message with same hash as a given one
      • Pre-image Attack: find a message that produces a given hash
  • Asymmetric Cryptography
    • Everyone has one public and one private key
    • Symmetric Crypto Problem: shared secrets and not scalable.
    • Diffie–Hellman Key Exchange
      • Asymmetric protocol used to establish a shared symmetric key
      • Allows secure key exchange over an insecure channel
      • Often used before switching to faster symmetric encryption
    • Asymmetric Secure Channel
      • Uses asymmetric cryptography to establish trust
      • Once established, switches to symmetric encryption for efficiency
    • RSA Cryptography
      • Public key encryption scheme
      • Supports both encryption and digital signatures
    • Integrity & Authenticity
      • Message is signed using the sender’s private key
      • Signature is verified using the sender’s public key
      • Ensures the message was not altered and confirms the sender
    • Confidentiality
      • Message is encrypted using the recipient’s public key
      • Message is decrypted using the recipient’s private key
      • Only the intended recipient can read the message
    • Key Usage Summary
      • Public key → encrypt or verify
      • Private key → decrypt or sign
    • Bleichenbacher’s Attack
      • Attack on RSA implementations
      • Exploits small values or improper padding
      • Can recover plaintext by taking mathematical roots
  • Application Security
    • Buffer Overflow
      • Program uses more memory than was allocated
      • Often occurs on the stack
      • Can overwrite important data or control flow
    • Integer Overflow
      • A very large integer wraps around to a small value
      • Can lead to incorrect memory allocation or logic errors
    • Code Injection
      • Attacker injects code (e.g., shellcode) into a payload
      • Injected code is then executed by the program
    • Code Reuse
      • Redirects control flow to unintended existing code
      • Avoids injecting new code
    • Shellcode
      • Malicious payload executed after exploitation
      • Common goal is spawning a shell (e.g., execve("/bin/sh"))
      • Often escalates privileges (e.g., setuid(0))
    • Return-Oriented Programming (ROP)
      • Attacker chains together existing code snippets
      • Uses multiple return instructions
      • Works well on x86 due to CISC instruction set
    • Pointer Dereferencing
      • Using pointers to access or modify memory
      • Example: overwriting variables via manipulated pointers
      • Can allow arbitrary memory access
    • Address Space Layout Randomization (ASLR)
      • Defense that randomizes memory locations on each execution
      • Makes buffer overflow attacks harder
      • Often defeated using NOP sleds
    • Data Execution Prevention (DEP)
      • Defense makes stack and heap non-executable
      • Prevents direct execution of injected code
      • Encourages code-reuse attacks instead
    • Unsafe Functions
      • Functions like gets() and strcpy() allow buffer overflows
      • Should be avoided or replaced with safer alternatives
    • Stack Canaries
      • Special values placed on the stack
      • Detect if stack memory has been overwritten
  • Web Security
    • Security when interacting with web sites.
    • SQL injection attacks
      • Inject valid sql syntax into server that will run
      • Bypass logins, extract user data, modify data.
      • Delete data, escalate privileges, take over server
      • Prevention: Don't confuse code with data
    • Cross-Site Request Forgery (CSRF)
      • Browsers automatically resend cookies (user session)
      • By crafting URL's an attacker can get indirect access without logging in.
      • GET attacker spies on data retrieved using state.
      • Violates Same Origin Policy (SOP): ensure user action originates from our website
      • Prevention: Server verifies that CSRF token within POST request matches form
    • Cross-Site Scripting Attack (XSS)
      • User submits malicious code to the server, server sends code back to user.
      • Persistent: Server saves malicious code in database, any user get served JS.
      • Reflected: attacker crafts URl with malicious code. User uses link and code is served back from the server and executed.
    • Browser Security
      • Use HTTPS! DOM mirroring, JS rendering off, Sandboxing
  • Network Security
    • Packet Sniffing: act of capturing and inspecting network packets
    • Email Spoofing: attacker forges address to appear as a different sender
    • Man-in-the-middle attacks
      • Attacker secretly intercepts, relays, alters communication between parties
      • Easy if using an unencrypted protocol.
    • Denial of Service (DoS)
      • Make server/service unusable
      • fork() bomb
      • Many other ways to consume resources
    • Distributed Denial of Service (DDOS)
      • Bot master has botnet
      • SYN flooding attacks
      • Ping of death (larger than acceptable packet)
      • ICMP smurf attack, ARP flooding, Attacks on physical layer
  • Malware
    • Malware: malicious software designed to steal data, cause damage, or take control of a system
    • Spyware: secretly monitors user activity and collects information without consent
    • Ransomware: encrypts a user’s system or files and demands payment to restore access
    • Virus: self-replicating software that infects other programs and requires user action to spread
    • Worm: self-replicating malware that spreads automatically over networks
    • Rootkit: gives attackers persistent, hidden control over a compromised system
    • Botnet: network of infected computers controlled remotely by a botmaster

Data Structures and Algorithms

1/6/2024

  • Data Structures
    • Arrays: A contiguous block of memory, offering fast indexing but fixed size.
    • Linked Lists: A linear structure where elements are connected by pointers.
    • Stack: A LIFO (Last In, First Out) data structure
    • Queue: A FIFO (First In, First Out) structure
    • Graphs: Represent networks of nodes and edges.
    • Binary Heap: A complete binary tree structure used to implement priority queues efficiently.
    • Binary Tree: A tree where each node has at most two children, used in searching and hierarchical data storage.
    • HashTables/HashMaps: Provide fast lookups by hashing keys to indices in an array.
    • Huffman Trees: Used for data compression by assigning variable-length codes to input characters based on frequencies.

  • Algorithms

    • Searches

    • Sequential Search: A simple search method that checks each element in order.
    • Binary Search: An efficient search algorithm for sorted data, with O(log n) complexity.

    Sorts

    • Bubble Sort: A basic sorting algorithm that repeatedly swaps adjacent elements until sorted.
    • Insertion Sort: Builds the sorted array one element at a time by inserting elements into their correct positions.
    • Selection Sort: Sorts by repeatedly finding the smallest element and moving it to the front.
    • Quick Sort: A divide-and-conquer algorithm that uses a pivot to partition the array and recursively sort partitions.
    • Merge Sort: A stable, divide-and-conquer algorithm that merges sorted subarrays into a single sorted array.

    Graph Algorithms

    • Depth First Search (DFS): Traverses graph/tree structures deeply along branches before backtracking.
    • Breadth First Search (BFS): Explores graph/tree structures level by level, ideal for finding the shortest path.
    • Dijkstra's Algorithm: Finds the shortest path in a graph with non-negative edge weights.
    • Tree Traversal Algorithms: Methods like in-order, pre-order, and post-order for visiting tree nodes systematically.
